# 轻提示（Toast）与对话框（Alert）使用规范

Kissly 的临时反馈统一使用 `src/ui/app-toast.tsx`，不要在各页面里再手写浮层。只有需要用户做决定或跳转时才使用 `appAlert`。

## 1. 选择哪种反馈



| 场景             | 组件                    | 示例                       |
| -------------- | --------------------- | ------------------------ |
| 操作成功、结果通知、约束提示 | Toast（success / info） | 已保存、导入完成、已在订阅中           |
| 失败、异常、不可用      | Toast（error）          | 连接失败、导出失败、无法朗读           |
| 删除、清空、重置等破坏性操作 | Alert                 | 确定删除 3 条历史记录？            |
| 需要用户选择或跳转      | Alert                 | 未配置 API（去配置）、发现新版本（下载安装） |

判断规则：



* 只有一个 “确定” 按钮、点完什么都不会变的提示，一律用 Toast。

* 有两个及以上按钮，或需要用户确认 / 选择 / 跳转的，用 Alert。

* 表单里的持续错误（例如校验失败）优先用页面内错误文字；一次性结果用 Toast。

## 2. 视觉语义



* `success`：绿色对勾 + 绿色系底色，默认 1 秒。

* `error`：红色感叹号 + 红色系底色，默认 2.5 秒。

* `info`：中性紫 / 白底 + 信息图标，默认 1.5 秒。

成功和失败不能长得一样，至少同时具备 “图标 + 颜色” 两重区分。

## 3. 代码用法



```
import { toast } from '../../src/ui/app-toast';

toast.success('翻译引擎与密钥已保存');
toast.info('还没有订阅，先添加频道再导出');
toast.error(`连接失败：${message}`);

// 全屏播放页需要避开底部控制栏
toast.success('已收藏视频', { bottomOffset: 120 });
```

`AppToastHost` 已在 `app/_layout.tsx` 挂载一次，页面不需要再渲染 Toast。多条提示连续触发时，后一条替换前一条，不排队堆积。

## 4. 文案要求



* 成功：动词 + 对象，如 “已保存”“已添加「频道名」”。

* 失败：`动作 + 失败：原因`，如 “导出失败：没有写入权限”。

* 不把堆栈、HTML 响应、超长调试信息直接展示给用户；详细原因写日志，Toast 只保留一行能行动的信息。

* 不在 Toast 里放 “请点击确定” 之类需要用户操作的文案；需要操作就用 Alert 或页面按钮。

## 5. 已迁移范围

原先 31 处单按钮通知型 Alert 已改为 Toast（订阅、历史 / 收藏、播放页、翻译、WebDAV、更新、导出、语音等）。保留的 14 处均为删除 / 重置确认，或带 “去配置 / 去设置 / 下载安装 / 查看发布页” 的决策对话框。

新增页面时不要再引入页面级 `toastTimer` / `setToast` 状态；直接调用 `toast.*`。
